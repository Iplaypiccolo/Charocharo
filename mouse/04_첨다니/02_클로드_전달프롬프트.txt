첨다니 한 캐릭터의 로그인 화면 마우스 액션 「신호가 통했나? 쫑긋·빙긋」을 구현해줘.
이번에는 첨다니만 작업한다. 기존 길통이·차로차로·티라와 로그인 인트로를 유지하며 다른 친구나 타자 입력 모션을 새로 만들지 않는다.

[전체 장면 맥락]
친구들이 정면으로 달려와 환영하고, 문구·폭죽이 펼쳐지는 슬로우 장면을 거친 뒤 첨다니가 공중제비로 정렬하고 모두 작아져 로그인 화면에 남는다. 지금 구현할 것은 이 인트로가 끝난 뒤의 마우스 반응이다. 공중제비를 마우스 반응에도 반복 적용하지 않는다.

[원본과 현재 코드 확인]
chumdani/chumdani.json, rig.json, README.md와 실제 로그인·모션 에디터 연결 코드를 먼저 읽어줘.
첨다니는 입이 없는 정면 버스다. 앞 유리 중앙 구분선과 원래 차체를 유지하고 새 입·손·팔을 붙이지 않는다. 기쁨은 눈·눈썹·귀·안테나·와이파이로 표현한다.
현재 구조는 rig→flip→body이고 귀·안테나·바퀴·눈·눈썹·신호는 body 자식이다. 이번 가벼운 몸 기울임은 body를 사용하고 공중제비용 flip은 회전시키지 않는다.
기본 stage=400×400, rig pivot=(627,700), rig rest=(200,215), scale=0.2. body pivot=(627,990)이다. 로그인 화면에서 별도 배치·배율을 쓰고 있다면 그 값을 유지한다.

[추가 이미지 두 장]
01 눈_빙긋공용: 굵고 둥근 ∩ 곡선 한 개. 좌우 눈 두 곳에서 재사용.
02 효과_발견반짝: 노란 네 갈래 반짝임 한 개. 안테나 공 옆에 작게 표시.
두 PNG는 1254×1254 투명 배경이며 내장 이미지 생성 출력 원본 그대로다. 추가파츠_조립정보.json의 source_rect→guide_draw_rect로 현재 좌표계에 조립한다. 파일 전체를 같은 좌표에 단순 오버레이하면 맞지 않는다.
Canvas drawImage 9인자 방식으로 source_rect를 target에 그려도 되고, JSON의 full_png_variant_rect를 이용해 현재 렌더러의 images variant로 넣어도 된다. 후자는 그림 파일을 자르거나 재인코딩할 필요 없이 PNG 전체의 배치 상자를 맞추는 방식이다.
새 눈의 부모는 body, 그림 중심은 기존 왼쪽 (479.5,620), 오른쪽 (774.5,619.5)에 맞춘다. 기본 그림 영역은 각각 72×34. 현재 점눈을 숨긴 상태에서 새 눈을 보여 두 겹이 되지 않게 한다.
반짝임은 ant 자식, 기본 그림 영역 x719,y190,w84,h108 정도. 공과의 간격을 유지하고 기본 op=0, 액션에서만 켠다. 실제 작은 표시 크기에서 공과 겹치면 더 작게 하거나 위치만 조금 조정한다.

[기본 따라보기]
양쪽 기존 점눈을 같은 방향으로 최대 원본 10px 정도 이동시킨다. 기본 무대에서는 약 2px이며 실제 표시 배율에 비례한다. 눈썹은 눈의 25%만 따라간다.
차체는 평소 최대 좌우 1도, 귀는 2도 이내, 안테나는 0.1초 정도 늦게 2도 이내로 가볍게 반응한다. 위치는 실제 그려진 캐릭터 경계를 기준으로 정규화한다.
시간 기반 보간을 사용하고 현재 rAF 루프에 통합한다. mousemove마다 타이머·렌더링 루프를 만들지 않는다. 캐릭터 전체가 커서 쪽으로 이동하거나 바퀴가 굴러가게 만들지 않는다.

[시작·방향·재시작]
캐릭터 경계 및 주변 약 0.25H 안에서 커서가 0.9초 머무르면 시작한다. H는 화면 표시 높이. 약 14 CSS px 넘게 움직이면 머무름 시간을 다시 센다.
시작 시 왼쪽/오른쪽 방향을 고정한다. 가운데 작은 구간에서는 마지막 방향, 이전 방향이 없으면 왼쪽을 선택한다.
약 2.6초 한 번 재생 후 계속 머물러도 반복하지 않는다. 영역 이탈 후 재진입이 필요하고 시작 간격은 최소 5초다.
다른 친구와 영역이 겹치면 가장 가까운 한 캐릭터만 시작한다. 다른 친구가 이미 동작 중이면 갑자기 끊지 말고 첨다니는 대기한다.

[표정 세 개]
A 기본: 기존 기본 점눈·기본 눈썹.
B 관심: 기존 점눈 sx=sy=1.08, 커서 쪽 눈썹 y=-8, 먼 눈썹 y=-3.
C 빙긋: 양 눈을 새 빙긋 눈으로 교체, 눈썹은 기존 기본 그림에서 y=-4.
입은 만들지 않는다. 눈·눈썹을 같은 순간에 전환하고, 긴 크로스페이드로 점눈과 빙긋 눈이 겹치지 않게 한다. 액션 중 자동 follow와 자동 깜빡임은 잠시 중단하고 시작 방향의 시선을 키로 유지한다.

[와이파이 — 기존 조각 재사용]
wifi0=약함 외곽, wifi1=강함 점, wifi2=강함 안쪽, wifi3=강함 바깥이다. 각각 별도 part이므로 이미지 인덱스로 단계가 바뀐다고 가정하지 않는다.
wifi0은 계속 켜 두고 그 위에 wifi1/2/3의 op를 순차적으로 올린다. 기본 대기는 세 강함 조각이 모두 1이다.
신호는 감정 표시일 뿐 실제 통신·서버 상태·로그인 진행률·키 입력과 연결하지 않는다. ‘연결 성공’ 같은 시스템 메시지를 추가하지 않는다. 신호에 귀나 안테나 회전을 복사하지 않고 차체에 고정한다.

[타임라인 — 머무름 조건 충족 이후]
0.00~0.20초: A→B. 눈이 먼저 알아차림. 강함 조각은 0.15초 동안 사라져 약함 외곽만 남는다.
0.20~0.85초: B 유지. 가까운 귀 위로 12도, 먼 귀 위로 3도. body 최대 커서 쪽 2도, ant 같은 쪽 4도. wifi1 0.30초, wifi2 0.48초, wifi3 0.66초에 차례로 켠다. 점만→점+안쪽→점+안쪽+바깥의 누적 순서다.
0.85~1.20초: B→C. 양 귀 위로 8도. ant는 같은 쪽 5도까지 잠깐 갔다가 3도로. 반짝임이 0.7→1.08→1 크기로 조용히 등장한다. 회전·이동보다 op와 작은 축척으로 나타낸다.
1.20~1.70초: C 유지. 차체 1% 이내 눌림 한 번. 강함 세 조각의 op를 함께 1→0.7→1로 한 번만 부드럽게 변화시킨다. 반짝임은 1.45~1.65초에 사라진다. 계속 깜빡이는 루프를 쓰지 않는다.
1.70~2.60초: 차체가 먼저 바로 선다. ant는 약 0.12초, 귀는 약 0.18초 늦게 작은 반동 후 정착. 약 2.05초에 A로 눈·눈썹 동시 복귀하고 신호는 원래 강함 3단계를 유지한다. 현재 커서 위치로 부드럽게 추적을 다시 연결한다.
이후: A 유지. 재진입 전까지 자동 반복하지 않는다.

[회전·접지]
모든 회전은 기존 rest에 대한 변화량이다. 귀를 위로 올리는 방향은 왼쪽 +, 오른쪽 -다. 커서가 왼쪽이면 earL +12, earR -3; 오른쪽이면 earR -12, earL +3이다.
body는 오른쪽 +2도, 왼쪽 -2도. ant도 같은 부호를 사용한다. 차체나 그림을 통째로 반전하지 않는다.
body는 rig 자손이라 body.y 추가값은 원본 좌표 단위다. 기본 pose에서 바퀴 바닥을 유지하기 위한 시작값은 -2도일 때 -7.819, -1도 -3.919, +1도 -3.876, +2도 -7.735다. 기본 stage에서의 이동량은 이 값×0.2이다. 실제 배율과 숨쉬기 합성에 맞춰 검수하고 중복 보정하지 않는다.
귀 뿌리·안테나 밑부분이 차체 뒤에 남아야 한다. 최대 12도·5도에서 틈이 보이면 먼저 각도를 줄인다. rest 배치·피벗·차체 비율을 전역 수정하지 않는다.

[중도 취소·입력 우선순위]
영역을 떠나면 현재 자세에서 0.35~0.5초 동안 A로 복귀. 반짝임은 0.1초 안에 끄고 신호는 강함 3단계로 부드럽게 복귀한다. 남은 신호 순서를 강제로 끝까지 재생하지 않는다. 창 밖 이탈은 가운데 시선으로 돌아온다.
인트로·입력 중·비밀번호·로그인 전환은 마우스보다 우선한다. 비밀번호 포커스 중에는 추적을 끄고 기존 프라이버시 동작이 있다면 우선한다. 이번에 새 타자 반응이나 비밀번호 동작은 만들지 않는다.
폼 입력·클릭을 표시 레이어가 가로채지 않게 한다. 모션 감소에서는 귀·안테나·차체 흔들림·반짝임·순차 점등을 생략하고 작은 눈 추적 및 고정 강함 신호만 쓴다. 터치 전용 기기에서는 마우스 액션을 자동 실행하지 않는다.

[검수·보고]
1. 조립미리보기와 실제 A/B/C를 같은 크기로 비교. 입을 새로 붙이지 않고 눈이 앞 유리 경계를 넘지 않아야 함.
2. 좌우 방향을 각각 확인해 귀와 눈썹, ant 방향이 맞는지 검수.
3. 신호 단계가 순서대로 누적되고 차체에 고정되는지 확인. 실제 서버 상태와 연결되지 않아야 함.
4. 0.25배 속도에서 귀·안테나 뿌리 틈, 접지, 반짝임과 공의 간격, 프레임 잘림 확인.
5. 커서 빠른 이동, 중도 이탈, 반복 진입, 창 밖 이탈, 창 크기 변경 확인.
6. 다른 캐릭터·기존 인트로 공중제비·원래 신호 연출이 유지되는지 확인.
수정 파일, 수동 재생 방법, 실제 확인한 항목과 남은 검수 항목을 보고해줘.
