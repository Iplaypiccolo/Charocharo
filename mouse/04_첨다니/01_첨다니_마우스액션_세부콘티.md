# 첨다니 마우스 액션 — 「신호가 통했나? 쫑긋·빙긋」

첨다니 하나의 마우스 액션이다. 친구들이 달려와 환영하고 작아져 로그인 화면에 자리 잡은 뒤 사용한다. 기존 인트로의 공중제비·정렬 동작은 유지한다.

## 캐릭터 방향

첨다니는 원래 입이 없는 정면 버스다. 앞 유리의 중앙 구분선과 차체를 유지하고 새 입을 붙이지 않는다. 작은 점눈과 눈썹, 귀, 안테나, 와이파이 신호로 관심과 기쁨을 표현한다. 티라의 덜컥거림이나 차로차로의 파닥임보다 차분하게, 귀가 쫑긋한 뒤 신호가 한 번 차오르고 눈으로 빙긋 웃게 한다.

한 액션의 표정은 A 기본, B 관심, C 빙긋의 세 가지다. 표정이 바뀔 때 눈·눈썹을 같이 전환한다. 입·손·팔·새 차체는 만들지 않는다. 이번 마우스 액션에는 점프·공중제비·이동이 없다.

## 현재 파츠

현재 chumdani.json은 차체·귀 좌우·안테나·바퀴 좌우·눈·눈썹과 와이파이 네 조각으로 구성된다. 눈 두 개와 눈썹은 이미 분리되어 있어 그대로 추적할 수 있다.

와이파이는 wifi0(약함 외곽) 위에 wifi1(강함 점), wifi2(강함 안쪽), wifi3(강함 바깥)을 겹쳐 켜는 구조다. 새 와이파이 그림을 만들지 않는다. 원래 대기에서는 세 강함 조각이 모두 켜져 있다.

추가 PNG는 두 장이다.

- 눈_빙긋공용: 굵고 둥근 반달 곡선 한 줄. 같은 그림을 양쪽 눈에 사용한다.
- 효과_발견반짝: 안테나 공 옆에 잠깐 나오는 작은 노란 네 갈래 반짝임.

원본 선은 회색에 가까운 짙은 색이다. 차로차로의 남색을 그대로 가져오지 않고 첨다니의 눈·귀 윤곽을 기준으로 맞춘다.

## 기본 커서 추적

양쪽 기본 눈이 같은 방향으로 최대 원본 좌표 10px 정도 움직인다. 기본 0.2배 무대에서는 약 2px이며 실제 표시 배율에 비례한다. 눈썹은 눈 이동의 25% 정도만 따라간다.

차체 기울기는 평소 최대 1도. 귀는 커서 방향을 알아차리는 정도로 2도 이내, 안테나는 눈보다 약 0.1초 늦게 2도 이내로 따라온다. 캐릭터가 커서 쪽으로 화면을 이동하지 않는다. 원래 앞 유리와 차체 형태를 휘거나 새 눈동자·흰자·하이라이트를 그리지 않는다.

## 시작 조건

첨다니의 실제 표시 경계 및 주변 약 0.25H 안에서 커서가 0.9초 머무르면 시작한다. H는 실제 캐릭터 높이이며 약 14 CSS px 넘게 움직이면 머무름 타이머를 다시 센다.

시작 순간 방향을 고정한다. 커서가 왼쪽이면 화면 왼귀, 오른쪽이면 오른귀가 먼저 반응한다. 가운데 작은 구간에서는 직전 방향을 유지하고 처음부터 가운데면 왼쪽을 선택한다. 차체 전체를 좌우 반전하지 않는다.

한 번 약 2.6초 재생한다. 커서가 계속 있어도 반복하지 않는다. 영역 밖으로 나갔다 다시 들어와야 하고 시작 간격은 최소 5초다. 다른 친구와 영역이 겹치면 가장 가까운 한 명만 시작한다.

## 세부 콘티

아래 시간은 머무름 조건이 충족되어 액션이 시작한 순간부터 센다.

| 시간 | 장면 | 표정 | 귀·안테나·신호 |
|---|---|---|---|
| 대기 | 차분하게 커서 따라보기 | A 기본 점눈·눈썹 | 기존 강함 3단계 유지, 잔잔한 호흡 |
| 0.00–0.20초 | ‘어?’ 하고 알아차림 | B: 기본 점눈을 1.08배, 가까운 눈썹 8px·먼 눈썹 3px 위 | 눈이 먼저 고정 시선. 강함 조각은 0.15초 동안 사라져 약함 외곽만 남음 |
| 0.20–0.85초 | 귀를 쫑긋 세우고 신호 탐색 | B 유지 | 가까운 귀 위로 12도, 먼 귀 위로 3도. 차체는 커서 쪽 최대 2도, 안테나는 같은 쪽 4도. 0.30초 점 → 0.48초 안쪽 → 0.66초 바깥 순으로 강함 조각 추가 |
| 0.85–1.20초 | ‘통했네!’ 하는 기쁜 반응 | C: 양 눈을 새 빙긋 눈으로, 눈썹은 기본보다 4px 위 | 두 귀를 위로 8도. 안테나는 5도까지 잠깐 갔다가 3도. 안테나 옆 반짝임이 작게 등장 |
| 1.20–1.70초 | 조용히 만족하며 웃음 | C 유지 | 차체 1% 이내 작은 눌림 한 번. 신호는 모두 켠 채 밝기 1→0.7→1로 한 번만 부드럽게 변화. 반짝임은 1.45–1.65초에 사라짐 |
| 1.70–2.60초 | 차분하게 기본으로 | 약 2.05초에 A로 함께 전환 | 차체가 먼저 바로 서고 안테나는 0.12초, 귀는 0.18초 늦게 작은 반동 후 정착. 신호는 원래 강함 3단계 유지 |
| 이후 | 커서만 따라보기 | A | 재진입 전까지 반복하지 않음 |

신호는 캐릭터의 감정 연출이다. **실제 인터넷 연결, 서버 상태, 로그인 진행률, 비밀번호 입력과 연결하지 않는다.** ‘연결 성공’ 같은 문구도 띄우지 않는다.

### 회전과 기준점

수치는 모두 현재 rest에 대한 추가 회전이다. 왼귀를 올릴 때는 +, 오른귀를 올릴 때는 -다. 예를 들어 왼쪽 12도 올리기는 earL +12, 오른쪽 12도 올리기는 earR -12다.

커서가 오른쪽일 때 차체는 +2도, 왼쪽이면 -2도. 안테나도 오른쪽 +4도, 왼쪽 -4도로 움직인다. 안테나·귀의 회전을 신호 파츠에 복사하지 않는다. 와이파이는 차체에 붙어 있는 표시다.

현재 rig는 무대 배치, flip은 공중제비 축, body는 차체 하단 축이다. 이번 가벼운 기울임은 body를 사용하고 flip에는 회전을 넣지 않는다. 바퀴는 이미 body 자식이다. 기울일 때 낮아진 쪽 바퀴의 바닥 높이에 맞춰 body.y를 보정한다. 보정값은 JSON의 원본 좌표 기준 값을 참고하고 현재 로그인 화면 배율에 맞게 검수한다.

## 이미지 조립

새 PNG는 1254×1254 투명 캔버스의 독립 파츠다. 기존 파츠는 잘린 이미지를 원본 좌표에 배치해 쓰므로, 새 그림도 `추가파츠_조립정보.json`의 source_rect 영역을 guide_draw_rect에 맞춰 그린다. 파일 전체를 같은 좌표에 단순 오버레이하지 않는다.

기존 눈 그림 중심은 왼쪽 (479.5,620), 오른쪽 (774.5,619.5)다. 새 빙긋 눈은 같은 중심에 72×34 정도로 배치한다. 눈 부모는 body이며 원래 점눈은 C 동안 숨겨 두 눈이 겹치지 않게 한다.

반짝임은 ant 자식으로 두고 안테나 공의 오른쪽 위에 작게 배치한다. 안테나가 기울어도 공과 간격을 유지한다. 눈 위나 앞 유리 중앙에 합쳐 그리지 않는다. 새 효과의 기본 op는 0으로 두고 이 액션에서만 켠다.

## 중도 이탈

어느 단계든 커서가 영역을 떠나면 현재 자세에서 0.35–0.5초 동안 A로 복귀한다. 반짝임은 0.1초 내에 먼저 끄고, 와이파이는 전체 강함으로 부드럽게 돌아간다. 남은 신호 순서를 끝까지 강제로 재생하지 않는다. 창 밖 이탈도 눈을 가운데로 돌린다.

액션 중에는 자동 눈 추적과 자동 깜빡임을 잠시 막고 시작 방향을 유지한다. 빙긋 곡선이 커서 이동에 따라 앞 유리 안에서 미끄러지지 않게 한다. 복귀 후 현재 커서 위치로 부드럽게 연결한다.

## 구현 후 검수

1. A/B/C에서 눈·눈썹이 원래 앞 유리 안에 있고 중앙 구분선을 넘지 않아야 한다. 입을 추가하지 않는다.
2. 좌우 방향을 각각 확인해 가까운 귀와 먼저 올라가는 눈썹이 맞는지 본다. 차체 전체 반전이나 좌우 귀 색·형태 교환은 하지 않는다.
3. 약함 외곽과 점·안쪽·바깥 신호가 현재 위치에 겹쳐 켜져야 한다. 귀·안테나가 흔들려도 신호는 차체에 고정된다.
4. 눈은 표정 세 가지를 넘기지 않는다. C에서 기존 점눈과 새 빙긋 눈이 겹치거나 자동 깜빡임이 끼어들지 않아야 한다.
5. 최대 귀·안테나·차체 각도에서 연결부 틈과 바퀴 접지, 캔버스 잘림을 확인한다. 반짝임이 안테나 공이나 이웃 캐릭터를 가리지 않아야 한다.
6. 빠른 커서 이동, 중도 이탈, 반복 진입, 창 밖 이탈, 창 크기 변경을 확인한다. 같은 자리에서 계속 재시작하지 않아야 한다.
7. 인트로·입력·비밀번호·로그인 전환이 마우스보다 우선한다. 다른 캐릭터가 이미 동작 중이면 갑자기 끊지 말고 대기한다. 이번에 타자 입력 동작을 만들지 않는다.
8. 표시 레이어가 폼 클릭을 가로채지 않아야 한다. 모션 감소에서는 귀·차체·안테나·반짝임을 생략하고 작은 눈 추적과 고정 강함 신호만 쓴다. 터치 전용 기기에서는 마우스 액션을 자동 실행하지 않는다.
