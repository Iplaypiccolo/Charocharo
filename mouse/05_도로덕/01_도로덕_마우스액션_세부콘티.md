# 도로덕 마우스 액션 — 「빼꼼…들켰덕!」

도로덕 하나의 마우스 액션 제작 자료다. 환영 인트로가 끝나 친구들이 작아져 로그인 화면에 남은 이후에 사용한다. 기존 인트로와 팻말 연출은 유지한다.

## 연출 방향

커서를 유심히 보던 도로덕이 한쪽 눈을 가늘게 뜨고 몸을 빼꼼 기울인다. 들킨 듯 잠깐 멈칫한 뒤 눈웃음을 짓고 작은 날개로 ‘나 아무것도 안 했는데?’ 하듯 한 번 으쓱한다. 마지막에 발끝만 꼼지락하고 제자리로 돌아온다.

부리는 원래 붉은 타원 하나를 유지한다. 벌어짐·입 안 선·치아·혀·부리 색 변화는 넣지 않는다. 표정은 A 기본, B 짝눈 관찰, C 눈웃음 세 종류다. 도로덕에 없는 눈썹이나 머리 관절을 새로 가정하지 않는다.

차로차로의 두 번 파닥임과 다르게, 도로덕 날개는 한 번 들어 으쓱한 뒤 천천히 내린다. 티라의 불꽃이나 첨다니의 반짝임 같은 효과도 추가하지 않는다. 몸의 기울임·멈칫·작은 발 움직임만으로 장난스러움을 만든다.

## 현재 파츠와 추가 이미지

현재 도로덕은 몸통(머리 포함), 좌우 눈, 붉은 타원 부리, 좌우 날개, 좌우 발이 분리되어 있다. 기본 점눈과 웃는 눈도 이미 있다. 새 그림은 **집중 눈 한 장**만 추가한다.

새 집중 눈은 윗변이 수평이고 아래가 둥근, 낮은 반타원 형태의 회색 점눈이다. 눈꺼풀 선·흰자·하이라이트·눈썹을 넣지 않는다. 커서에서 먼 쪽 눈에만 사용하고 가까운 눈은 기존 점눈을 유지한다. 같은 새 그림을 왼눈·오른눈에 공용으로 쓴다.

팻말과 팻말 앞가림용 wingRf는 로그인 마우스 대기·액션 모두 숨긴다. 오른날개를 움직일 때 숨겨진 팻말이 따라 나타나거나 날개가 두 장 겹쳐 보이지 않게 한다.

## 기본 따라보기

양쪽 기본 눈이 같은 방향으로 따라간다. 다만 원래 눈과 부리 간격이 작으므로 일반 캐릭터와 같은 상하 범위를 쓰지 않는다.

- 좌우 이동: 원본 좌표 ±8px 정도.
- 위쪽 이동: 최대 6px.
- 아래쪽 이동: 최대 1px. 기본 눈 그림 아래가 y489, 부리 그림 위가 y493이므로 아래로 크게 움직이면 겹친다.
- 기존 beak의 자동 follow는 이번 로그인 마우스 상태에서 끄고 부리를 원래 얼굴 위치에 고정한다. 원본 부리 픽셀·모양·비율은 바꾸지 않는다.
- 몸은 커서 방향으로 최대 1.5도만 늦게 기울인다. 머리가 몸통에 포함되어 있으므로 머리만 별도로 돌리는 모션은 쓰지 않는다.
- 원래 웃는 눈이나 새 집중 눈에는 자동 추적을 더하지 않는다. 액션 중에는 시작 시점 방향의 고정 시선을 키로 넣고, 끝나면 현재 커서 추적으로 연결한다.

## 시작 조건

도로덕의 실제 표시 경계 및 주변 약 0.25H 안에서 커서가 0.8초 머무르면 시작한다. H는 표시된 캐릭터 높이이며 약 14 CSS px 넘게 움직이면 머무름 시간을 다시 센다.

시작 순간 좌우 방향을 고정한다. 커서가 왼쪽이면 왼눈을 기본 점눈, 오른눈을 새 집중 눈으로 한다. 오른쪽이면 반대다. 몸 기울임과 발 역할도 함께 바꾼다. 전체 캐릭터를 좌우 반전하지 않는다.

한 번 약 2.8초 재생하고 같은 자리에서 반복하지 않는다. 영역 이탈 후 재진입이 필요하며 시작 간격은 최소 5초다. 다른 친구와 영역이 겹치면 가장 가까운 한 명만 새 액션을 시작한다.

## 세부 콘티

아래 시간은 0.8초 머무름 조건 충족 후 액션이 시작한 순간부터 센다.

| 시간 | 장면 | 표정 | 몸·날개·발 |
|---|---|---|---|
| 대기 | 커서 따라보기 | A 기본 점눈 두 개 | 몸은 아주 조금 늦게 따라감. 부리는 고정 |
| 0.00–0.25초 | ‘뭐지?’ 하고 유심히 보기 | B: 먼 눈은 새 집중 눈, 가까운 점눈은 가로만 1.12배 | 눈이 먼저 고정 시선. 몸은 커서 반대쪽으로 1도 살짝 망설였다가 기울기 시작 |
| 0.25–0.80초 | 몸을 길게 빼꼼 | B 유지 | 커서 쪽으로 몸 최대 4도. sy=1.025, sx=0.985 이내. 먼 발을 바깥으로 6px·위로 6px·바깥 회전 8도 이내 한 번 꼼지락 |
| 0.80–1.10초 | ‘앗, 들켰나?’ 하고 멈칫 | B 유지 | 0.15초 정도 자세를 멈춤. 날개나 발을 계속 흔들지 않음 |
| 1.10–1.65초 | 시치미 떼며 눈웃음 | C 기존 웃는 눈 두 개 | 몸은 커서 쪽 1.5도로 돌아오고 원래 크기로. 날개를 왼쪽 +28도·오른쪽 -28도 정도 한 번 으쓱 |
| 1.65–2.30초 | 아무 일 없다는 듯 태연 | C 유지 | 날개를 천천히 내림. 발끝은 한 번만 작게 꼼지락. 점프나 반복 파닥임 없음 |
| 2.30–2.80초 | 기본으로 복귀 | A로 양 눈 동시 전환 | 몸이 먼저 바로 서고 날개는 0.1초 늦게 작은 반동 후 정착 |
| 이후 | 커서만 따라보기 | A | 재진입 전까지 재생하지 않음 |

부리는 A/B/C 모두 같은 이미지와 같은 위치·크기를 사용한다. 전체 몸의 회전·축척을 함께 받는 것 외에 부리만 늘이거나 열지 않는다.

## 회전·접지·레이어

현재 body는 부모가 없는 루트이고 피벗은 (627,995), 기본 무대 위치 (190,332), 배율 0.26이다. 회전은 기존 rest에 더하는 값이다. 오른쪽 기울임은 +, 왼쪽은 -다.

날개를 올리는 방향은 왼쪽 +, 오른쪽 -다. 으쓱은 28도에서 시작해 실제 연결 틈을 보고 줄인다. 날개는 몸통 뒤에 둔 원래 레이어를 유지하며, 볼을 짚는 손처럼 얼굴 앞으로 올리지 않는다.

발은 몸통 뒤에 있어 위로만 들면 숨는다. 먼 발의 꼼지락은 왼발이면 x=-6, y=-6, rot=-8도, 오른발이면 x=+6, y=-6, rot=+8도처럼 바깥 방향을 섞는다. 실제 발끝이 보이는 범위로 줄인다. 가까운 발은 바닥을 유지한다.

기울임과 작은 늘이기 동안 body.y를 보정해 낮아진 발바닥의 높이를 유지한다. JSON에 원본 발 알파로 구한 접지용 외곽점과 기본 발바닥 높이 계산 기준을 넣는다. body가 루트인 현재 구조에서는 바닥의 기준 높이−현재 발바닥 최대 y만큼 body.y에 더하면 된다. 실제 로그인 부모 변환이 추가되어 있다면 부모 역변환으로 이동량을 환산한다.

## 이미지 배치

새 PNG는 1254×1254 투명 캔버스의 독립 파츠다. source_rect를 guide_draw_rect로 매핑하거나 full_png_variant_rect를 현재 엔진의 이미지 배치에 사용한다. 후자는 PNG 전체의 투명 여백을 포함한 배치를 계산한 값이므로 픽셀 파일을 자를 필요가 없다.

기본 눈 그림 중심은 왼쪽 (572,464), 오른쪽 (682.5,464)다. 새 눈은 같은 중심에 52×30 정도로 넣는다. 기존 점눈은 해당 눈에서 숨겨 원래 그림이 뒤에 남지 않게 한다. 새 눈의 부모는 body다.

## 중도 이탈과 우선순위

커서가 영역을 벗어나면 어느 단계든 현재 자세에서 0.35–0.5초 동안 A로 복귀한다. 남은 으쓱·꼼지락을 끝까지 강제로 재생하지 않는다. 창 밖으로 나가면 시선을 가운데로 돌린다. 다시 들어와도 중간 자세가 순간적으로 초기화되지 않게 한다.

인트로·입력·비밀번호·로그인 전환이 마우스보다 우선한다. 이 작업에서는 타자 반응이나 새 비밀번호 동작을 만들지 않는다. 기존 다른 친구의 액션이 이미 시작되었다면 갑자기 끊지 말고 도로덕을 대기시킨다.

## 검수

1. 모든 표정에서 부리가 같은 붉은 타원이고 안쪽 선·입 벌림이 없어야 한다.
2. 기본 눈의 아래쪽 이동과 B의 가까운 눈에서 부리와 겹치지 않아야 한다. B의 가까운 눈은 가로만 확대한다.
3. 왼쪽/오른쪽 커서에 따라 먼 눈만 집중 눈으로 바뀌어야 한다. C는 기존 웃는 눈 두 개로 함께 전환한다.
4. 몸을 기울일 때 발바닥 기준을 유지하고, 먼 발이 몸통 뒤로 사라지거나 바깥으로 너무 멀리 튀지 않아야 한다.
5. 날개 으쓱 최대 각도에서 뿌리 틈·검은 단면이 보이지 않아야 한다. 이 경우 레이어를 바꾸기보다 각도를 줄인다.
6. 팻말·팻말 글자·wingRf가 남아 있지 않아야 한다. 다른 친구·입력창을 가리거나 프레임 밖으로 잘리지 않아야 한다.
7. 빠른 커서 이동·중간 이탈·재진입·창 밖 이탈·크기 변경을 확인한다. 같은 자리에서 반복 재생하지 않아야 한다.
8. 모션 감소에서는 빼꼼·으쓱·발 동작을 생략하고 작은 시선 추적만 유지한다. 터치 전용 기기에서는 자동 마우스 액션을 실행하지 않는다. 폼 클릭은 표시 레이어가 가로채지 않게 한다.
