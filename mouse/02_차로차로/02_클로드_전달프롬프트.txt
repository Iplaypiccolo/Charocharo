차로차로의 로그인 화면 마우스 액션 「여기 봐! 파닥·찡긋」을 구현해줘.
이번 범위는 차로차로 하나다. 길통이의 기존 작업과 다른 친구들, 로그인 인트로는 유지하고 타자 입력 모션은 아직 새로 만들지 않는다.

[전체 장면 맥락]
친구들이 정면으로 우다다닥 달려와 환영 인사를 하고, 환영합니다 문구·폭죽이 나오는 슬로우 장면을 거쳐 각자 자리에 작아져 로그인 화면에 남는다. 지금 작업할 것은 이 인트로가 끝난 뒤의 마우스 반응이다. 등장·슬로우·정렬 연출을 바꾸는 작업이 아니다.

[먼저 확인할 파일]
현재 저장소의 charo-pet.json, ABOUT.md, charo-pet.js와 실제 로그인 화면·모션 에디터의 연결 코드를 확인해줘. 기존 그림을 새 그림으로 전부 교체하지 않는다.
GPT가 현재 사이트에서 확인한 charo-pet.json에는 눈·눈썹·입이 각각 다섯 장 들어 있다. ABOUT의 더 많은 전체 표정 목록이 현재 JSON에 모두 존재한다고 가정하지 않는다. 이번에는 기본 눈·기본 눈썹·기본 미소와 기존 몸통·양 날개를 재사용한다.
intro-cast.js 주소는 GPT 조회 때 404여서 해당 파일 이름을 전제로 코딩하지 말고 실제 최신 저장소의 로그인 연결 파일을 찾아줘.

[추가 이미지]
추가파츠 폴더에 투명 PNG 세 장이 있다.
01 입_호기심: 작고 약간 기울어진 남색 세로 타원.
02 입_찡긋웃음: 남색 웃는 입에 노란 혀 하나.
03 눈_윙크공용: 둥근 끝의 단순한 ∩ 곡선 한 줄.
윙크 눈은 좌우 공용으로 쓰고 커서 쪽 눈 하나에만 적용한다. 반대쪽은 기존 기본 눈이다. 치아·주름·속눈썹 등 추가 선은 그리지 않는다.

[중요: 그림 배치]
새 PNG는 모두 1254×1254이며 독립 파츠다. 파일 전체를 원본 위에 단순 오버레이하지 않는다. 추가파츠_조립정보.json의 source_rect를 guide_draw_rect에 맞춰 기존 원본 좌표계로 넣는다. Canvas drawImage 9인자 방식 또는 현재 엔진의 asset/variant 방식에 맞는 동등한 배치를 사용해줘.
현재 stage=400×400, body pivot=(626,1094), rest=(199.35,371.22), scale=0.26이다. 기존 좌표·배율을 바꿔 새 그림에 맞추지 않는다.
기본 입의 이미지 중심은 (628.5,683.5), 회전 기준점은 (628,730)이다. 새 입 중심을 730에 놓으면 아래로 튀므로 이미지 중심에 맞춘다.
왼쪽 기본 눈 그림 중심은 (454,564.5), 오른쪽은 (802,565.5)다. 새 윙크 눈은 같은 중심에 놓는다.
새 입과 윙크 눈의 부모는 body. 기존 눈·입을 끈 채 새 표정을 표시하고, 기존 그림이 뒤에 남아 두 겹이 되지 않게 한다. 기존 얼굴 파츠의 리스트 순서와 원래 인트로 그림은 보존한다.

[기본 따라보기]
캐릭터의 실제 화면 중심과 크기로 커서 방향을 정규화한다. 양쪽 눈은 동일 방향, 최대 원본 좌표 12px 정도. 현재 0.26배 기준 무대 약 3.1px이며 표시 배율에 비례한다.
눈썹은 눈의 25%만 움직이고 입의 follow는 끈다. 몸 기울기는 평소 최대 1.5도. 다리나 바퀴 파츠가 따로 있다고 가정하지 않는다. 이번에는 바퀴 회전·점프·비행을 하지 않는다.
시간 기반 보간으로 연결하고 기존 렌더링 루프에 통합한다. 매 mousemove마다 새 애니메이션·타이머를 쌓지 않는다.

[시작과 방향 선택]
차로차로 실제 화면 경계 및 주변 약 0.25H에서 커서가 0.65초 머무르면 시작한다. H는 표시된 캐릭터 높이. 커서가 약 14 CSS px 넘게 움직이면 머무름 타이머를 다시 센다.
커서가 왼쪽이면 파란 날개와 왼눈, 오른쪽이면 빨간 날개와 오른눈을 선택한다. 가운데 작은 구간에서는 마지막 방향을 유지하며, 이전 방향이 없다면 왼쪽을 선택한다. 액션이 시작되면 방향을 끝날 때까지 고정한다.
그림 전체를 반전하지 않는다. 좌우 파란색·빨간색의 위치는 그대로다.
한 번 약 2.4초 재생 후 커서가 남아 있어도 반복하지 않는다. 영역 이탈 후 재진입이 필요하고 시작 간격은 최소 4초다.

[표정 세 개 — 눈·눈썹·입 동시 전환]
A 기본: 기존 기본 눈 두 개, 기본 눈썹, 기본 미소.
B 호기심: 기존 눈 sx=sy=1.04, 양 눈썹 원본 y=-8, 새 호기심 입.
C 찡긋: 커서 쪽 눈만 새 윙크 눈, 반대는 기본 눈, 눈썹은 기본, 새 찡긋 웃음 입.
긴 크로스페이드로 눈이 겹쳐 보이지 않게 한다. 눈 확대·눈썹 이동은 80~120ms 안에서 연결해도 된다.

[타임라인 — 머무름 충족 후 시작]
0.00~0.25초: A→B. 눈이 먼저 관심을 보이고 몸이 커서 쪽으로 2도 기울기 시작. 날개는 잠깐 그대로.
0.25~0.60초: B 유지. 가까운 날개를 위로 약 14도, 먼 날개는 약 3도. 몸 기울기 최대 3도. 약 0.08초 멈칫.
0.60~1.15초: B 유지. 가까운 날개부터 두 번 파닥, 먼 날개는 약 0.08초 늦게 따라옴. 가까운 날개 최대 18도 후 12도, 먼 날개 10도 후 7도. 한 번 크게, 다음 작게. 몸 sx/sy 변화는 2% 이내. 점프하지 않음.
1.15~1.65초: B→C. 커서 쪽 눈을 찡긋하고 웃는다. 양 날개를 내리다가 가까운 날개만 약 8도 들고 잠깐 정지. 몸 기울기 약 2도.
1.65~2.40초: 몸이 먼저 바로 서고 날개는 0.1초 늦게 작은 반동 후 정착. 약 1.95초에 A로 동시 전환. 새 윙크 눈은 한 번만 사용.
이후: A로 현재 커서를 부드럽게 다시 따라본다. 같은 자리에서 자동 재생하지 않음.

[회전 부호와 접지]
날개 회전은 기존 rest에 대한 추가 변화량이다. 왼쪽 날개를 올리는 방향은 +, 오른쪽을 올리는 방향은 -다. 양 날개에 같은 부호를 적용하지 않는다.
몸을 오른쪽으로 기울임=+3도, 왼쪽=-3도. 원본 그림을 반전하지 않고 동작 값과 먼저 움직일 파츠만 바꾼다.
body pivot은 바퀴 아래 가운데다. 몸을 기울일 때 낮아지는 쪽 바퀴가 바닥을 뚫거나 전체가 떠 보이지 않도록 body.y를 함께 보정한다. 원본 알파를 기준으로 계산한 기본 400 무대의 시작값은 -3도일 때 y=-3.759, -2도=-2.506, +2도=-2.479, +3도=-3.718이다. 각도 사이에는 연속 보간하되 현재 화면의 바닥 기준에 맞게 확인한다. 다른 배율에는 비례 적용한다. 기존 숨쉬기 y와 중복 누적하지 않는다.
날개 뿌리는 몸통 뒤 레이어 유지. 최대각에서 틈이 생기면 각도를 줄인다. rest 피벗·배율을 전역으로 바꿔 기존 동작이 달라지게 하지 않는다.

[중도 취소와 우선순위]
도중에 커서가 영역을 벗어나면 현재 자세에서 0.35~0.5초에 걸쳐 A로 돌아온다. 남은 파닥임과 윙크를 강제로 재생하지 않는다. 창 밖 이탈도 가운데로 복귀한다.
액션 중에는 자동 follow와 자동 깜빡임을 잠시 막고 시작 시점의 커서 방향으로 시선을 고정한다. 윙크 곡선이 자동 추적으로 미끄러지지 않게 한다.
길통이와 영역이 겹치면 가장 가까운 한 캐릭터만 반응한다. 다른 캐릭터가 이미 동작 중이라면 차로차로를 대기시켜 갑자기 끊지 않는다. 이번 구현을 위해 다른 친구들 모션을 새로 만들 필요는 없다.
로그인 인트로, 입력 중, 비밀번호, 로그인 전환이 마우스 액션보다 우선한다. 비밀번호 포커스 중에는 마우스 시선을 끄고 기존 프라이버시 동작이 있으면 우선한다. 이번에는 타자 입력 모션을 추가하지 않는다.
표시 레이어는 폼 클릭을 가로채지 않게 한다. 모션 감소에서는 파닥·기울기·윙크 액션을 생략하고 작은 눈 추적만 유지한다. 터치 전용 기기에서 마우스 액션을 자동 반복하지 않는다.

[검수]
1. 조립미리보기.html과 실제 A/B/C 포즈를 같은 크기로 비교. 표정·입 위치가 튀지 않아야 함.
2. 왼쪽·오른쪽 방향을 각각 재생해 가까운 날개와 윙크 눈이 맞는지 확인.
3. 0.25배 속도로 날개 뿌리 틈, 접지, 겹침, 캔버스 잘림 확인. 정적 가이드의 18도 극값에서는 400 무대 안에 들어오지만 실제 연속 구간·축척·호흡 합성도 별도로 검수할 것.
4. 빠른 커서 이동, 출입 반복, 창 밖 이탈, 창 크기 변경 확인. 한 번만 재생 조건과 중도 복귀 확인.
5. 길통이와 동시 출발하지 않고 인트로·입력·비밀번호·로그인에 간섭하지 않는지 확인.
6. 기존 인트로·날고 싶어 모션·다른 캐릭터가 유지되는지 확인.
수정 파일, 수동 재생 방법, 실제 확인한 항목과 확인하지 못한 항목을 보고해줘.
